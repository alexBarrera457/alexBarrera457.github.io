Contexto del proyecto: de la nube a la soberanía de datos local

La mayoría de asistentes de inteligencia artificial dependen íntegramente de servidores remotos cerrados, lo que plantea problemas de privacidad, latencias impredecibles y falta de control sobre el historial personal. OMNI // NEXUS nació para explorar cómo construir una capa de inteligencia local, rápida y soberana:

⚠️ Limitaciones de clientes IA tradicionales

  • Tus conversaciones, consultas y código residen en infraestructuras ajenas.
  • Incapacidad de ejecutar herramientas locales precisas (reloj del sistema, cálculos matemáticos sin sesgo).
  • Interfaces lentas y sobrecargadas con modelos de suscripción mensuales obligatorios.
  • Ausencia de una base de datos local inspectable con formato SQL estándar.

💡 Solución implementada en OMNI // NEXUS

  • Runtime local en Express 5 con seguridad HTTP estricta (Helmet, rate limiting por IP).
  • Base de datos SQLite persistente con consultas instantáneas y esquema relacional abierto.
  • Sistema de herramientas desacoplado que resuelve operaciones matemáticas y temporales en milisegundos.
  • Modo DEMO offline automático para operar incluso sin conexión o sin API keys configuradas.

Arquitectura técnica y principios de Deep Modules

El sistema aplica de manera rigurosa la filosofía de Deep Modules (John Ousterhout): módulos con interfaces estrechas que ocultan implementaciones ricas y complejas:

⚡

Backend Express 5 Modular

  • Servidor Desacoplado: server.js condensado en menos de 90 líneas legibles y testeables.
  • Routers Dedicados: Controladores específicos para /api/chat, /api/conversations, /api/memory y /api/health.
  • Seguridad por Defecto: Protección integral con helmet, límites de payload a 256kb y rate limiter en memoria.
  • Inyección de Dependencias: Repositorios y servicios inyectados como fábricas para permitir mocks limpios en tests.
💾

Persistencia SQLite & Repositorios

  • better-sqlite3 en WAL Mode: Write-Ahead Logging para permitir lecturas y escrituras concurrentes sin esperas.
  • Esquema Relacional Estricto: Tablas nexus_conversations y nexus_messages con claves foráneas y ON DELETE CASCADE.
  • Repositorios Ocultos: Métodos limpios (getConversations, createConversation, deleteConversation) sin exponer SQL al exterior.
  • Memoria Opcional: Tabla memories para extracción y persistencia de preferencias de usuario a largo plazo.
🧠

Nexus Service & Tool Routing

  • Planificación de Herramientas: Detección automática en dos fases (plan y ejecución) entre CALCULATOR, CLOCK y WEB SEARCH.
  • Evaluador Matemático Seguro: Parser aritmético propio en lib/calculator.js con precedencia de operadores y sin eval().
  • Modo DEMO Resiliente: Fallback sin fallo que resuelve cálculos y respuestas de demostración cuando el LLM no está accesible.
  • Frontend Reactivo en Astro 5: Canvas procedural con órbitas y partículas estelares, navegación accesible y feedback de estado en vivo.

Repositorio y ejecución local

El proyecto cuenta con suite de tests, tooling de calidad (ESLint, Prettier) y puesta en marcha en un único comando:

bash · omniroute-test · node v24 
# Instalar dependencias
npm install

# Ejecutar suite de pruebas (27 tests unitarios e integración)
npm test

# Iniciar servidor Express y frontend en http://127.0.0.1:3000
npm start

# Verificar salud del runtime y herramientas activas
curl http://127.0.0.1:3000/api/health
